# Q5: open defects from verify round 4 (main session hands them to the repair)

1. tests/story-data.test.ts, the case 'every talk stage has exactly one way on': it counts only options pinned to stage i (`movers(...).filter(m => m.stages.includes(i))`), so it misses two kinds of option that also move the stage. One is a reachable option in the same tree with `advance` (or `finish`) on the quest and no stage pin, for example `when: {quest:[id,'active']}`; the rule in dialogue.ts accepts it at any talk stage, and the once-only check skips it because it pays nothing. The other is such an option in another person's tree. Either way, Q6 data that lets a player skip a talk stage would pass. Count unpinned options as ways, and scan every person's tree, not only `st.at`.
2. tests/support/satisfy.ts, `satisfy`: for an `any` condition it only tries `cond.any[0]`, and it throws on a `not` whose inner condition is true, while its doc comment promises 'its first workable branch'. A valid `needs` such as ml_wards' 'chain finished, or a save that never had the chain', written with its `not` branch first, makes the walk go red on correct data. Try each branch on a `cloneState` copy and keep the first that holds, or correct the comment and document the ordering constraint.
3. tests/story-data.test.ts, `condIdProblems`: it checks quest, stage, skill, has, stat and shrine leaves but not claimed, starter or flag leaves, and `claimOld` in satisfy.ts claims any id it is given. A typo such as `{claimed:'ml_ward'}` in a quest's `needs` or `done` passes both the id check and the walk, yet that quest could never be offered in play. Check those leaves against the claimable ids, the starter ids and the boolean flag keys, as dialogue-data.test.ts's `condProblems` already does (reuse that function rather than keeping two near-copies).
4. tests/dialogue-data.test.ts line 30: `dungeons.DUNGEONS ?? []` is a new defaulting fallback. Once Z1 creates src/data/dungeons.ts, a missing or renamed `DUNGEONS` export would silently become an empty list instead of failing. Default only when the file is absent (for example, have `optionalModule` return the named export, and throw when the file exists but the export does not). The same applies to the impossible-state guard `edges.get(n) ?? []` at line 155.
